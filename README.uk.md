# CashDriver

[English](README.md) · [Español](README.es.md) · **Українська**

### Готівкові оплати водія — решта, чайові та історія в одному застосунку.

**CashDriver** — Android-застосунок для водіїв таксі та сервісів перевезень. Він допомагає швидко порахувати решту, врахувати чайові й бачити підсумки готівкових оплат за день, тиждень або місяць. Працює **офлайн**, без реєстрації та обов’язкового сервера.

Вибери платформу → введи вартість поїздки й отриману готівку → перевір решту → підтвердь оплату. Запис автоматично з’явиться в історії та підсумках.

> Підтримувана платформа — **Android 7.0+**. Інтерфейс: **Español / English**. Валюта: **EUR**. iOS наразі не підтримується; APK не встановлюється на iPhone.

## Чим допомагає CashDriver

- **Решта без ручних підрахунків.** Введення через кому або крапку, швидкі суми та дія «Exacto» для оплати без решти.
- **Окремий облік чайових.** Зазнач конкретну суму або залиш всю решту як чайові.
- **Історія під рукою.** Пошук потрібного періоду через календар, фільтр платформи, деталі, редагування та видалення з можливістю Undo для окремої операції.
- **Зрозумілі підсумки.** Вартість поїздок, чайові, залишена готівка, кількість операцій, середня вартість поїздки й розподіл за платформами.
- **Налаштування під роботу.** Uber, Cabify, Bolt і Taxi; світла, темна й автоматична теми; окремі перемикачі звуку та вібрації з кнопкою перевірки.

**Приклад:** поїздка коштує **20 €**, клієнт дає **50 €**, чайові — **5 €**. Повернути потрібно **25 €**; готівка, яка залишається у водія, — **25 €**: вартість поїздки плюс чайові.

Платформи — це вибрані вручну мітки. CashDriver не підключається до їхніх облікових записів. Підсумок готівки не враховує витрати чи комісії та не є розрахунком прибутку.

SQL залишається в repositories, грошові правила — у доменних функціях, а React hooks керують завантаженням і станом екранів. Особиста база не використовується для тестового наповнення. Тестові entrypoints не імпортуються production-застосунком.

**Дані зберігаються лише на пристрої.** Хмарної синхронізації, резервного копіювання та відновлення зараз немає. Видалення застосунку або очищення його сховища може назавжди стерти історію. Для запису оплат інтернет не потрібен; Automatic може запитати приблизне місцезнаходження після явного вибору цього режиму.

## Як зібрати APK

Нижче — послідовність для **Windows / PowerShell**. Команди запускаються з кореня завантаженого або клонованого проєкту.

### 1. Підготуй середовище

Потрібні:

- Node.js **22.11.0+** та npm.
- **JDK 17** з налаштованим `JAVA_HOME`.
- Android Studio / Android SDK: **Platform 37**, **Build-Tools 37.0.0**, **NDK 27.1.12297006** — версії задані в `android/build.gradle`.
- SDK, доступний через `ANDROID_HOME` або локальний `android/local.properties` із `sdk.dir`.

Для першого завантаження залежностей потрібен інтернет. **Телефон, емулятор і Metro не потрібні для створення release APK.**

### 2. Встанови залежності

```powershell
npm ci
```

### 3. Налаштуй release-підпис

Для оновлення вже встановленого CashDriver потрібен **той самий ключ**, яким підписана попередня release-версія. Використовуй чинний ключ проєкту; не створюй заміну для звичайного перебілду.

Gradle читає файл:

```text
%USERPROFILE%\.cashdriver\signing\release.properties
```

Приклад структури файла — заміни значення власними, не публікуй паролі:

```properties
storeFile=C:/path/outside/repository/cashdriver-release.p12
storePassword=YOUR_STORE_PASSWORD
keyAlias=YOUR_KEY_ALIAS
keyPassword=YOUR_KEY_PASSWORD
```

Формат сховища ключа — **PKCS12**. Інший шлях до properties-файла можна передати лише для поточного PowerShell-сеансу:

```powershell
$env:CASHDRIVER_SIGNING_PROPERTIES = 'C:\path\outside\repository\release.properties'
```

Ключ і properties-файл тримай поза Git; збережи їхню резервну копію. Якщо підпис не налаштований, release-збірка зупиниться — debug-підпис автоматично не підставляється. У власника проєкту підпис уже може бути налаштований: тоді цей крок повторювати не потрібно.

### 4. Перевір проєкт і збери

```powershell
npm run typecheck
npm run lint
npm run format:check
npm test -- --runInBand
```

Якщо перевірки успішні:

```powershell
cd android
.\gradlew.bat assembleRelease
cd ..
```

Дочекайся **BUILD SUCCESSFUL**. Готовий підписаний файл:

```text
android/app/build/outputs/apk/release/CashDriver.apk
```

Відкрити його папку з кореня проєкту:

```powershell
explorer.exe .\android\app\build\outputs\apk\release
```

Після наступних змін повтори перевірки та `assembleRelease`: файл `CashDriver.apk` буде оновлений. `clean` щоразу не потрібен.

## Як перенести APK і встановити на телефон

1. **Отримай файл.** Використай зібраний `CashDriver.apk`. Якщо файл надано тобі для встановлення, завантаж саме APK із довіреного джерела на телефон. Цей README не містить посилання на опублікований APK.
2. **Перенеси через USB**, якщо APK на комп’ютері: підключи Android, вибери режим «Передавання файлів» і скопіюй APK, наприклад, у папку `Download` телефона.
3. **Відкрий APK** через «Мої файли» / файловий менеджер. За запитом Android дозволь цьому файловому менеджеру встановлення з цього джерела.
4. Натисни **«Встановити»** або **«Оновити»**, дочекайся завершення й відкрий **CashDriver**. Після встановлення дозвіл на невідомі застосунки для файлового менеджера можна вимкнути.

За наявності ADB і ввімкненого USB debugging можна встановити з комп’ютера:

```powershell
adb devices
adb install -r .\android\app\build\outputs\apk\release\CashDriver.apk
```

Цей приклад передбачає один підключений Android-пристрій. Якщо їх кілька, явно вкажи потрібний через `adb -s SERIAL install -r ...`.

### Оновлення та збереження історії

- Application ID: **`com.alexm.cashdriver`**. Для звичайного оновлення зберігай його та чинний ключ підпису.
- Перед новим розповсюджуваним релізом збільш `versionCode` у `android/app/build.gradle`, а `versionName` зміни відповідно до версії. Для кожної локальної спроби збірки номер змінювати не потрібно.
- **Якщо Android повідомляє про несумісний підпис — не видаляй старий застосунок.** Причиною може бути спроба встановити release поверх debug-версії. Видалення старої версії або очищення її даних стирає локальну історію; спочатку потрібно з’ясувати, яким ключем вона підписана.
- Прапорець ADB `-r` означає перевстановлення зі збереженням даних, але не обходить перевірку підпису та не замінює резервне копіювання.

## Запуск під час розробки

Для debug-режиму потрібен Android-емулятор або телефон із USB debugging. З кореня проєкту, у двох терміналах:

```powershell
# Термінал 1 — Metro
npm start
```

```powershell
# Термінал 2 — debug-збірка й запуск
npm run android
```

Debug-збірка призначена для розробки; для самостійного встановлення та роботи без Metro використовуй **release APK**. iOS-файли залишені в репозиторії для можливого майбутнього розвитку, але iOS-збірка й підтримка зараз не заявляються.

Для ізольованої перевірки великих баз використовується окрема команда `assembleAcceptance` у папці `android`. Вона створює пакет `com.alexm.cashdriver.acceptance` з тестовими даними. **Це не APK для щоденного використання.** Acceptance і release потрібно збирати окремими командами.
